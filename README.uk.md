# Gothic 3 ImpExp — аддон Blender для Gothic 3

[English](README.md) · **Українська**

Імпорт і експорт моделей, персонажів, анімацій і колізії **Gothic 3** (Piranha Bytes, 2006, рушій Genome) у
**Blender 5.1+** — прямо з архівів гри й назад у гру.

> **Стан: бета 0.9.** Усе, що пише аддон, звірено з файлами самої гри й прочитано назад через пошук файлів гри; замінені
> моделі, рельєф і їхню колізію перевірено в грі. Зробіть резервну копію й повідомляйте, що знайдете.

## Що він уміє

**File → Import** (пошук за назвою в межах категорії):

| Пункт | Файли гри | Що з'являється в Blender |
|---|---|---|
| Gothic 3 Model | `.xcmsh` + `.xshmat` + `.ximg` | меш з текстурами (вершини зварені, шви uv/нормалей збережені), налаштовані alpha test/blend і specular, і його колізія — каркасний дочірній об'єкт `<назва>_COL` (опукле тіло предмета — `<назва>_CV`). Категорії: предмети, будівлі, декор і меблі, рослини, локації, рельєф, вода, службові |
| Gothic 3 Character | `.xact` | скелет (кістки паличками) і меш зі шкінінгом, без анімації; тіло людини — з вибраною головою (типово голова Безіменного). Категорії: люди — тіло або голова, тварини й монстри, предмети й об'єкти |
| Gothic 3 Lip-sync | `.xlip` + `.ogg` мовлення | репліка гри (пошук за назвою, для кожної мови) на анімованій голові вибраного персонажа (`G3_Head_…_Animated_…`; її кістки обличчя приходять разом з Gothic 3 Character): дія на кістках обличчя і голос у відеоредакторі |
| Gothic 3 Animations | `.xmot` | анімації на вибраний скелет Gothic 3: одна або ціла категорія — стійка, рух, атаки, захист, діалоги й жести, сидіння й лежання, взаємодія, смерть |
| Gothic 3 Collision | `.xnvmsh` | лише колізія, каркасним мешем; по матеріалу `G3_Shape_<поверхня>` на кожну поверхню (камінь, дерево, земля…), і опукле тіло предмета. У клітинок рельєфу колізія — їхні ж трикутники |
| Gothic 3 World Layer | `.node` | що ставить один шар світу (пошук за назвою, напр. `ardea_dynamic_objects`) і в радіусі навколо — будинки й скелі статичних клітинок та рельєф: оточення, щоб будувати нову модель під місце, де вона стоятиме (розставляє її редактор світу). Кожен меш завантажується раз і з'являється в кожному місці як зв'язана копія |
| Gothic 3 Terrain | клітинки рельєфу `.xcmsh` | клітинки за назвою або навколо 3D-курсора однією сіткою для редагування, звареною через межі клітинок: матеріали гри, uv, кольори як атрибути кутів (`g3_diffuse`: альфа змішує шари землі; `g3_light`: запечена яскравість), додаткові набори uv Варанту, клітинка кожної грані (`g3_cell`) |

**File → Export** — три шляхи: **файл мода** `.g3mod` (типово; один файл у теці `Mods` гри, який лаунчер модів підключає й прибирає, і ним зручно ділитися), встановити одразу в гру або пакет з `INSTALL.bat` / `ROLLBACK.bat`:

| Пункт | Що пише |
|---|---|
| Gothic 3 Model → Mod | `.xcmsh` замість моделі гри з тією ж назвою або нову, нові матеріали (`.xshmat` за шаблонами гри: непрозорий, з блиском, з alpha test) і текстури (`.ximg`), колізію (`.xnvmsh`, з об'єктів `*_COL` або з самої моделі; у рельєфу — завжди з моделі) з поверхнями за матеріалами, і опукле тіло предмета (`*_CV`, з об'єктів `*_CV` або з форми самої моделі). Заміна моделі гри бере кольори вершин і освітлення (лайтмапи всіх її розміщень у світі) від найближчих старих вершин і заміняє також її `_lod1` |
| Gothic 3 Motion → Mod | `.xmot` замість однієї з анімацій гри (типово тієї, з якої прийшла дія) або нова анімація поруч (з назвою або наступним вільним варіантом тієї ж дії — гра грає анімацію за назвою, яку складає зі стану персонажа); IK та інші обмеження потрапляють як результат; ефекти кадрів (кроки, звуки) — зі списку дії, що редагується у вкладці Gothic 3 |
| Gothic 3 Terrain → Mod | змінені клітинки об'єкта рельєфу (форма, розфарбовані кольори, матеріали): меш, колізія з його трикутників, лайтмапа і плитки далекого вигляду землі над зміненим місцем; клітинка без змін лишається гри |
| Gothic 3 Actor → Mod | `.xact` — ваш меш на скелеті гри (броня, тіла, голови, істоти; кілька об'єктів Blender стають його одним мешем, по матеріалу на кожен), ваги з груп вершин |

Моди потрапляють у гру як том-латка на кожен архів (`Data\_compiledMesh.pNN` тощо, після власних томів гри) — так само,
як латки самої гри; архіви не змінюються. Гра перестає підключати томи на першому пропущеному номері, тому в
номерах ніколи немає дірок: том, що спорожнів під іншим, лишається порожнім, доки не стане останнім. Вкладка **Gothic 3** показує встановлені з Blender моди з кнопкою «прибрати».

Вкладка **Gothic 3** у бічній панелі 3D-вікна має все це, а коли вибрано скелет Gothic 3 — **риг для анімування**:
кольори й групи кісток, фігури, за які зручно хапати, і IK для рук і ніг (ціль і полюс на кожну кінцівку). Риг лише
додає кістки, які нічого не деформують; IK спершу вимкнено, а вмикання кінцівки ставить ціль точно в поточну позу.

## Встановлення

1. Blender 5.1 або новіший.
2. *Edit → Preferences → Get Extensions → ⌄ → Install from Disk…* → `gothic3_impexp-0.9.10.zip`.
3. У налаштуваннях аддона перевірте **Папка гри Gothic 3** (та, де лежить `Gothic3.exe`; шлях Steam уже
   підставлено).

Zip містить `gothic3-core.exe` — нативну частину (Windows x64). Більше нічого не потрібно — ні PhysX SDK, ні програм.
Встановлені моди лежать у `Gothic 3\gothic3_impexp\` (їхні файли й список) плюс по одному тому-латці на архів у `Data`.

## Швидкий старт

- **Замінити предмет:** Import → Gothic 3 Model → `G3_Object_Barrel_02`. Змініть його, не зсувайте початок координат.
  Export → Gothic 3 Model → Mod, та сама назва, *Встановити в гру*. Запустіть гру.
- **Нова броня:** Import → Gothic 3 Character → `G3_Hero_Body_Player`. Змініть меш тіла (лишіть шкінінг), виділіть лише
  його, Export → Gothic 3 Actor, та сама назва. Голова — окремий актор: виділіть лише її, щоб експортувати.
- **Змінити анімацію:** Import → Gothic 3 Character → істота, виділіть скелет, Import → Gothic 3 Animations. Змініть дію
  (допоможе риг для анімування), Export → Gothic 3 Motion: анімацію, з якої вона прийшла, уже вибрано.

## Обмеження

- Меші пишуться як у гри (елементи версії 5 з кольорами вершин і деревом сфер), але без другого набору uv: освітлення
  заміненої моделі пишеться вершинним (так у грі три чверті лайтмап), навіть якщо в гри воно було сторінками-текстурами.
- Далекі низькополігональні версії світу (`*_lowpoly`, `G3_World_Landscape_Lowpoly_*`) не замінюються.
- Колізію пакує бібліотека PhysX самої гри (`NxCooking.dll` з папки Gothic 3; аддон її не постачає) через 32-бітний
  помічник `g3cook.exe`. Трикутники колізії повернуті навпаки відносно меша, як у гри.
- Об'єкти світу звертаються до кожної частини колізії за її номером у файлі й дають їй власну поверхню. Тому колізія,
  що заміняє колізію гри, зберігає частини гри в її порядку: у клітинки рельєфу це матеріали меша, в об'єкта — поверхні
  (водяний млин: камінь, потім дерево). Поверхня, якої в колізії гри для цієї моделі немає, іде з першою частиною
  (експорт про це пише), а частина, що лишилася б порожньою, тримає один трикутник. Світ зберігає й стару рамку кожної
  частини: експорт попереджає, коли частина помітно за неї виходить.
- Опукле тіло предмета (`*_CV` — яким він лежить, падає й котиться) теж пакує PhysX гри: по оболонці на кожен об'єкт
  `*_CV` або оболонка самої моделі.
- Нова анімація бере анімацію гри за зразок (її кістки й структуру); новий актор — актора гри (його скелет; у всіх
  акторів гри один меш, яким разом стають кілька об'єктів Blender).
- Нова модель чи актор з'являються в грі лише тоді, коли щось їх розставляє або на них посилається.

## Примітки

- **Поверхня колізії** (звук кроків): панель матеріалу → Gothic 3 → *Поверхня колізії*. Авто — з назви: матеріали рельєфу
  гри мають свою (трава й лісова підстилка = clay, гравій = debris, стежки = earth, скелі = stone, пісок = sand), інші —
  за словами в назві (wood, metal, stone…), решта — типова з діалогу експорту.
- Імпорт кількох моделей з тим самим матеріалом гри дає один спільний матеріал (без `.001`), меші лишаються окремими.
- Gothic 3 рахує в сантиметрах; аддон імпортує з масштабом 0.01 (метри).
- Томи-латки (`.p00`, `.p01`, … Community Patch) читаються поверх основних архівів, як це робить гра.
- Доріжка анімації задана відносно найближчого предка, який теж має доріжку; службові кістки між ними
  (`*_ROOT`, `*_END`) під час програвання тримаються одиничними, як у грі.

## Збірка з вихідного коду

```sh
cd core && cargo build --release                          # gothic3-core.exe
cd core && G3_GAME="<тека Gothic 3>" cargo test --release   # тести на файлах самої гри
BLENDER=/path/to/blender.exe tools/build_release.sh       # dist/gothic3_impexp-<версія>.zip
blender -b --factory-startup --python tools/blender_check.py -- <тимчасова тека>   # прогін аддона в Blender
```

Що де перевірено й що відкрито — `STATUS.md`. Версії — `CHANGELOG.md`.
